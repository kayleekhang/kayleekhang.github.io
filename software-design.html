Software Design and Engineering Enhancement

Artifact Overview

The artifact chosen is my thermostat project from CS-350, which introduced me to the fundamentals of embedded systems development. The project involved developing a thermostat using a Raspberry Pi and a breadboard, including connections to buttons, LEDs, and an LCD screen. Through this project, I also gained experience working with serial communication protocols such as I2C.

Reason for Selection

I selected this artifact because I am interested in pursuing a career in embedded software engineering. While the original project successfully met functional requirements, it was not designed with scalability or maintainability in mind. The implementation consisted of a single monolithic file that mixed multiple concerns, lacked structure, and did not include clear separation between hardware interaction, business logic, and output. This made it a strong candidate for improvement through better software design practices.

Enhancements and Improvements

To improve the system, I refactored the original monolithic implementation into a modular architecture composed of separate Python modules. My approach focused on separating concerns and designing components that could operate independently while still working together as a cohesive system.

Original Design

In the original version, the thermostat logic, display behavior, hardware access, and serial communication were all combined into one file. This worked for a prototype, but it made the code harder to maintain and extend. 

class TemperatureMachine(StateMachine):
    off = State(initial=True)
    heat = State()
    cool = State()

    setPoint = 72

    cycle = (
        off.to(heat) |
        heat.to(cool) |
        cool.to(off)
    )

    def updateLights(self):
        temp = floor(self.getFahrenheit())
        redLight.off()
        blueLight.off()

        if self.current_state.id == "off":
            redLight.off()
            blueLight.off()
            return

        if self.current_state.id == "heat":
            blueLight.off()
            if temp < self.setPoint:
                redLight.pulse(fade_in_time=1, fade_out_time=1, background=True)
            else:
                redLight.on()
            return

        if self.current_state.id == "cool":
            redLight.off()
            if temp > self.setPoint:
                blueLight.pulse(fade_in_time=1, fade_out_time=1, background=True)
            else:
                blueLight.on()
            return

Refactored Design

In the enhanced version, I separated the system into focused modules. Each module has a single responsibility, which improves readability, maintainability, and flexibility. 

from sensor_manager import SensorManager
from database_manager import DatabaseManager
from serial_manager import SerialManager
from thermostat_controller import ThermostatController
from display_manager import DisplayManager

sensor = SensorManager()
db = DatabaseManager()
serial = SerialManager()
display = DisplayManager()

thermo = ThermostatController(sensor, db, serial)

while True:
    temp, action = thermo.update()
    display.update(temp, thermo.state, thermo.setpoint)
    sleep(5)

Example of Separation of Concerns

Instead of keeping all logic in one file, the redesigned system assigns responsibilities to dedicated classes. 

class SensorManager:
    def get_fahrenheit(self):
        t = self.sensor.temperature
        return ((9/5) * t) + 32
  
class SerialManager:
    def send(self, state, temp, setpoint):
        msg = f"{state},{temp},{setpoint}\n"
        self.ser.write(msg.encode())
  
class DisplayManager:
    def update(self, temp, state, setpoint):
        print(f"{state.upper()} | Temp: {temp}F | Set: {setpoint}F")
  
class ThermostatController:
    def __init__(self, sensor, db, serial):
        self.sensor = sensor
        self.db = db
        self.serial = serial
        self.state = "off"
        self.setpoint = 72

Key Design Improvements

  • Modular Architecture: Broke the application into multiple modules to improve readability and maintainability.
  • Composition-Based Design: Built the system from smaller components that work together instead of placing all functionality in one class.
  • Separation of Concerns: Sensor, display, serial communication, database, and controller logic were separated into dedicated modules.
  • Hardware Abstraction: Hardware-dependent code is isolated, making future replacements easier.
  • Extensibility: The design makes it easier to add features such as improved storage, new sensors, or additional communication methods.

System Design Overview

The redesigned system follows a composition-based architecture where the thermostat controller coordinates interactions between independent modules. Each module has a single responsibility, which reduces coupling and improves testability. This structure allows future enhancements, such as swapping sensors or adding new communication protocols, with minimal changes to the overall system.

Outcome and Impact

These improvements significantly enhanced the system’s modularity and maintainability. By separating concerns and using composition, the system is now easier to extend, debug, and adapt to new requirements. This approach reflects industry best practices for embedded systems design, where resource constraints and hardware dependencies require thoughtful architecture.
