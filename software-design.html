Software Design and Engineering Enhancement

Artifact Overview

The artifact chosen is my thermostat project from CS-350, which introduced me to the fundamentals of embedded systems development. The project involved developing a thermostat using a Raspberry Pi and a breadboard, including connections to buttons, LEDs, and an LCD screen. Through this project, I also gained experience working with serial communication protocols such as I2C.

Reason for Selection

I selected this artifact because I am interested in pursuing a career in embedded software engineering. While the original project successfully met functional requirements, it was not designed with scalability or maintainability in mind. The implementation consisted of a single monolithic file that mixed multiple concerns, lacked structure, and did not include data persistence. The thermostat logic relied on a basic state machine with minimal abstraction. This made it a strong candidate for improvement through better software design practices.

Enhancements and Improvements

To improve the system, I refactored the original monolithic implementation into a modular architecture composed of five separate Python modules. My approach focused on separating concerns and designing components that could operate independently while still working together as a cohesive system.

Key Design Improvements

  • Modular Architecture: Broke the application into multiple modules to improve readability, maintainability, and scalability.
  • Composition-Based Design: Used composition instead of inheritance, allowing components to be flexible and easily replaceable.
  • Database Integration: Introduced an SQLite-based module for logging thermostat data, supporting persistence in an embedded environment.
  • Separation of Concerns:
    • Display Manager handles all output logic
    • Sensor Manager abstracts temperature readings
    • Serial Manager handles communication protocols
    • Database Manager handles data storage
    • Thermostat Controller orchestrates the system
  • Hardware Abstraction: Designed modules so hardware components (e.g., sensors or communication protocols) can be replaced without impacting other parts of the system.

System Design Overview

The redesigned system follows a composition-based architecture where the thermostat controller coordinates interactions between independent modules. Each module has a single responsibility, which reduces coupling and improves testability. This structure allows future enhancements, such as swapping sensors or adding new communication protocols, with minimal changes to the overall system.

Outcome and Impact

These improvements significantly enhanced the system’s modularity and maintainability. By separating concerns and using composition, the system is now easier to extend, debug, and adapt to new requirements. This approach reflects industry best practices for embedded systems design, where resource constraints and hardware dependencies require thoughtful architecture.
